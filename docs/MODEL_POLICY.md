# Политика использования моделей (Model Governance)

Утверждено владельцем 12.11.2026 («Нулевой этап»). Обязательна для всех этапов, главной сессии и всех агентов. Имеет приоритет над последующими заданиями, пока владелец отдельно не разрешит её изменить.

## 1. Модели проекта

| Модель | ID | Роль |
|---|---|---|
| Claude Fable 5.2 | `claude-fable-5-2` | Главный управляющий: стратегия, постановка задач, управление агентами, ключевые архитектурные решения, сравнение концепций, разрешение противоречий, проверка качества, утверждение итогов этапов |
| Claude Opus 5.5 | `claude-opus-5-5` | Сложные задачи: креативные концепции, UX-архитектура, дизайн-система, сложные компоненты, калькулятор и математика, архитектура каталога, сложные анимации, SEO-стратегия, сложные технические проблемы, глубокая критика дизайна |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | Рутина: аудит и инвентаризация, перенос текстов и данных, стандартные компоненты, типовые страницы по утверждённому макету, метаданные по готовой SEO-стратегии, обычные тесты, проверка ссылок, простые ошибки, форматирование |

Других моделей (в т.ч. Haiku) в проекте не используем. Недоступную модель не подменяем молча — останавливаемся и сообщаем владельцу.

## 2. Как выбирать модель

- Простая, ограниченная, понятная задача → **Sonnet**.
- Сложная профессиональная задача, нужен анализ и инженерное мышление → **Opus**.
- Ключевое решение на несколько направлений, стратегия, серьёзное противоречие → **Fable**.

Запрещено: брать Fable для всего подряд только потому, что он главный; брать Opus для простых и повторяемых задач; поручать Sonnet стратегические и архитектурные решения. Модель не повышаем без реальной необходимости.

## 3. Эскалация

```
Sonnet ──(2 неудачные попытки ИЛИ сложная неоднозначность ИЛИ нужно архитектурное решение)──▶ Opus
Opus   ──(нужно менять общую стратегию ИЛИ пересматривать несколько согласованных решений)───▶ Fable
```

- Агент сам не эскалирует и не вызывает другого агента: он останавливается и возвращает отчёт с пометкой `ЭСКАЛАЦИЯ → Opus: <причина>` или `ЭСКАЛАЦИЯ → Fable: <причина>`.
- Главная сессия передаёт задачу агенту следующего уровня и записывает эскалацию в `docs/MODEL_USAGE_LOG.md`.
- Решения, меняющие согласованное с владельцем (CLAUDE.md), утверждает владелец — Fable готовит варианты.

## 4. Ограничение расходов

- Не запускать несколько дорогих моделей на одну простую задачу.
- Параллельно — только независимые задачи; без нужды всех агентов сразу не запускать.
- Один файл в один момент меняет только один агент (в задаче агенту — явный список файлов).
- Агенту передаём конкретную задачу и 1–3 нужных документа, а не всю историю проекта.
- Не повторяем анализ, уже качественно выполненный и записанный в `docs/`.
- Детерминированные операции (данные, ссылки, форматы, сборка, тесты, проверка конфигурации) — скриптами, не AI: `npm run build`, `npm test`, `node scripts/check-agents.mjs`.
- Каждый вызов агента стоит минимум ~0,1–0,25 $ даже на пустом задании (загрузка системного промпта и проекта; замер 12.11.2026). Поэтому мелочь на 1–2 правки главная сессия делает сама, а не через агента.
- Каждая существенная делегация — запись в `docs/MODEL_USAGE_LOG.md`.

## 5. Права агентов

- У каждого агента в YAML frontmatter явно указан `model:` полным ID и явный список `tools:` без `Agent` — агенты не могут создавать и вызывать других агентов (дополнительно среда ограничивает глубину вложенности = 1).
- Агентам запрещено менять: этот файл, `docs/AGENT_ROUTING.md`, `.claude/agents/`, раздел «Модели» в `CLAUDE.md`. Менять их может только главная сессия по прямому разрешению владельца.
- Скилы — только по прямой просьбе владельца (общее правило CLAUDE.md).
- Проверка соблюдения: `node scripts/check-agents.mjs` после любой правки `.claude/agents/`.

## 6. Главная сессия

Роль главного управляющего — у главной сессии, и по политике она должна работать на **Fable 5.2**. Модель главной сессии выбирает владелец (переключатель модели в приложении / `/model claude-fable-5-2`); агент сам её не меняет. Если главная сессия запущена на другой модели, ключевые решения и утверждение этапов передаются агенту `project-director` (Fable).

## 7. Проверка доступности (12.11.2026)

- Claude Code 2.1.322, облачная среда claude.ai, провайдер Anthropic API (`firstParty`, `api.anthropic.com`).
- Алиасы `fable`, `opus`, `sonnet` в инструменте Agent → `claude-fable-5-2`, `claude-opus-5-5`, `claude-sonnet-5-5` (проверено вызовами).
- Полные ID в frontmatter агентов работают: headless-прогон вызвал `project-director`, `frontend-engineer`, `content-auditor` (так агенты назывались при проверке 12.11.2026; текущий состав — `AGENT_ROUTING.md`); по биллингу (`modelUsage`) — ровно `claude-fable-5-2`, `claude-opus-5-5`, `claude-sonnet-5-5`.
- Новые файлы в `.claude/agents/` подхватываются только при старте новой сессии.

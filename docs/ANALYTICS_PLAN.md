# План аналитики нового сайта

Дата: 12.11.2026. Документ описывает, что и зачем измерять. Кода и настроек в кабинетах здесь нет — только проект.

Источники: `docs/FUNCTIONAL_MAP.md` (ФК, разделы 4, 7, 11.2), `docs/CONTENT_INVENTORY.md`, `docs/USER_SCENARIOS.md` (воронка и формы).

Оговорки:
- Кабинет Метрики мы не видели. Настроены ли там цели, сколько данных накоплено, откуда идёт трафик — неизвестно.
- Всё, что касается закона о персональных данных, — это пометки о риске, а не юридическое заключение. Решает владелец (при необходимости с юристом).
- Некоторые возможности Метрики описаны по её справке, как мы её помним. Перед внедрением их нужно проверить в кабинете (помечено «проверить»).

## 1. Главная мысль

Заказ в мастерской оформляет человек, а не сайт. Сайт приносит **обращение**: заявку, звонок, сообщение. Поэтому:
1. Главный показатель — число обращений и их сумма, а не посещаемость.
2. Самый надёжный источник правды о заявках — база заявок (таблица `orders`), а не Метрика. Метрика часть посетителей не видит (блокировщики рекламы, отключённые скрипты).
3. Метрика нужна, чтобы понять, **где люди теряются по дороге** к заявке.
4. Событий мало, и каждое отвечает на конкретный вопрос.

## 2. Какие инструменты нужны, а какие нет

### Нужны

| Инструмент | Зачем | Состояние |
|---|---|---|
| Яндекс Метрика | Посещения, источники, воронка, записи визитов | Счётчик стоит на старом сайте; оставляем тот же, чтобы не потерять историю |
| Яндекс Вебмастер | По каким запросам сайт показывают в поиске, ошибки индексации, переезд адресов | Файл подтверждения есть; при смене сайта его нужно сохранить |
| База заявок (Supabase, `orders`) | Точное число заявок, суммы, позиции, источник | Работает на старом сайте; нужно добавить поля (раздел 6) |
| Уведомления в Telegram | Владелец видит заявку сразу; туда же — источник заявки одной строкой | Работает |
| Свой чат | После запуска — ещё один канал обращений | Не запущен |

### Полезны, но необязательны

| Инструмент | Зачем | Замечание |
|---|---|---|
| Кабинет организации на Яндекс Картах и в 2ГИС | Там своя статистика: сколько раз из карточки позвонили и построили маршрут (проверить, что показывает кабинет) | Бесплатно; нужен доступ владельца. Это единственное место, где видны звонки «с карт» |
| Google Search Console | Запросы из поиска Google | Бесплатно; на сайт ставится только файл подтверждения, данные посетителей не передаются. Нужен, только если из Google заметный трафик (сейчас неизвестно) |

### Не нужны (и почему)

| Инструмент | Почему не нужен |
|---|---|
| Google Analytics | Дублирует Метрику. Данные посетителей уходят на серверы за границей — в российской практике это связывают с требованиями закона о персональных данных (трансграничная передача). Риск есть, пользы сверх Метрики для небольшого местного сайта нет. Ставить или нет — решает владелец; мы не рекомендуем |
| Google Tag Manager | Лишний слой: событий мало, их проще и надёжнее отправлять прямо из сайта. К нему те же замечания, что к Google Analytics |
| Коллтрекинг (подмена номеров) | Платный. Объём звонков неизвестен; без рекламных расходов окупить нечем. Вернуться к вопросу, если владелец начнёт платить за рекламу |
| CRM и сквозная аналитика | Платно, требует ежедневной дисциплины. Заявок, судя по всему, столько, что хватит таблицы заявок с отметкой «состоялся» (раздел 8) |
| Отдельные сервисы тепловых карт и записи экрана | В Метрике уже есть вебвизор и карта кликов |
| Сервисы А/Б-тестов | Для надёжного теста нужен большой поток посетителей; хватит ли его — неизвестно. Вернуться после 2–3 месяцев данных |
| Счётчики рекламных сетей (ВК и др.) | Нужны только при платной рекламе в этих сетях. Рекламы сейчас, насколько нам известно, нет |

## 3. Схема имён событий

Имя: `зона_действие` или `зона_действие_результат`, латиница, строчные буквы, подчёркивание.

Зоны: `product` (страница изделия), `calc` (калькулятор и смета), `file`, `form`, `contact`, `route`, `kp`, `chat`, `callback`.

Старые имена сохраняем там, где они уже подходят под схему, — чтобы не терять историю целей, если они были настроены.

**Общие параметры** (добавляются к событиям, где имеют смысл):

| Параметр | Значения | Замечание |
|---|---|---|
| `page` | путь страницы без параметров адреса | |
| `page_type` | `product`, `hub`, `price`, `b2b`, `article`, `home`, `other` | |
| `category`, `product` | коды из прайса (`textile`, `tshirt-unisex`) | |
| `client_type` | `private`, `company`, `unknown` | Как определяется — раздел 5 |
| `place` | где на странице: `header`, `mobile_bar`, `hero`, `calc`, `estimate`, `footer`, `contacts`, `success`, `error` | |
| `total` | сумма в рублях, целое число | Предварительная, не выручка |
| `items` | число позиций в смете | |
| `has_file` | `0` / `1` | |

**Чего в аналитику не передаём никогда:** имя, телефон, e-mail, название организации, ИНН, текст комментария и сообщений чата, имена файлов, текст поля «другой цвет» и других свободных полей.

### 4.1. Главные конверсии (то, что приносит заказ)

|---|---|---|---|---|
| `form_submit_success` | Сервер подтвердил, что заявка **сохранена**. Один раз на заявку (по номеру заявки). Если сервер ответил «принято» без сохранения — событие не шлём | `form_type` (`estimate`, `quick`, `b2b`, `callback`), `client_type`, `items`, `total`, `has_file`, `layout` (`ready`, `photo`, `none`), `contact_method`, `page`, `category` первой позиции. Сумма также передаётся как доход цели (проверить формат в справке Метрики) | Главный показатель сайта. | `contact_max_click` | Переход в MAX. Та же защита | `place`, `page`, `page_type` | То же | Новое |

### 4.2. Вспомогательные действия (шаги воронки и признаки интереса)

| Событие | Когда срабатывает, защита от повторов | Параметры | Какое решение помогает принять | Старое имя |
|---|---|---|---|---|
| `product_view` | Открыта страница изделия, услуги, хаба или страницы компаний. Один раз на загрузку страницы | `page`, `page_type`, `category`, `product` | Первый шаг воронки. Какие изделия смотрят, но не считают, — значит, первый экран не убеждает | Новое |
| `calc_start` | Первое осознанное действие в калькуляторе (смена изделия, параметра, количества, размера). Один раз на калькулятор за загрузку страницы. Открытие страницы с уже посчитанной ценой событием не считается | `category`, `product`, `page`, `entry` (`default`, `link` — пришёл по ссылке на расчёт, `preset` — из готового варианта) | Замечают ли калькулятор и пользуются ли им; на каких страницах его не трогают | Новое |
| `calc_change` | Первое изменение **каждого вида** параметра за один расчёт: не больше одного события на вид | `field` (`product`, `option`, `print_add`, `size`, `qty`, `qty_hint` — нажата наклейка скидки или подсказка, `own_item`, `color_other`), `category`, `product` | Какими настройками пользуются, а какие лишние; работает ли подсказка «ещё N шт — дешевле» | Новое |
| `calc_over_limit` | Количество превысило предел изделия, показано «индивидуальный расчёт». Один раз на изделие за загрузку | `category`, `product`, `qty_bucket` (`51-100`, `101-300`, `300+`) | Как часто людям нужен тираж больше предела; стоит ли расширять прайс или заметнее предлагать расчёт на группу и для компаний | Новое |
| `calc_add` | Позиция добавлена в смету любым способом. Одно событие на добавление | `source` (`calc`, `preset` — готовый вариант или идея, `free` — свободная строка), `category`, `product`, `qty`, `total`, `items` | Что кладут в смету; пользуются ли готовыми вариантами; собирают ли несколько позиций | Сохранить имя, добавить параметры |
| `calc_complete` | Человек перешёл от расчёта к оформлению: открылась форма с непустой сметой («Заказать» в калькуляторе или «Оформить» в смете). Один раз, пока состав сметы не изменился | `items`, `total`, `has_individual` (есть позиции «посчитает менеджер»), `page` | Сколько расчётов доходит до оформления. Разрыв между `calc_start` и `calc_complete` показывает, пугает ли цена или сам калькулятор | Заменяет `calc_order` |
| `file_attached` | Файл успешно прошёл проверку и добавлен. Одно событие на добавление (несколько файлов сразу — одно событие) | `place` (`calc`, `form`, `chat`), `count`, `kind` (`image`, `vector`, `pdf`, `archive`, `other`) | Где людям удобнее прикладывать файл; много ли приходит с готовым макетом | Сохранить имя; на старом сайте не срабатывало в калькуляторе — исправить |
| `form_open` | Открыта форма заявки. Одно событие на открытие | `form_type`, `place`, `page`, `page_type`, `items` | Какие кнопки и страницы открывают форму. Разрыв между `form_open` и отправкой — сама форма отпугивает | Переименовать из `order_open` |

| `form_submit_error` | Отправка не удалась. Одно событие на попытку | `reason` (`network`, `server`, `rate_limit`, `files`, `rejected`), `form_type`, `has_file` | Теряем ли заявки по техническим причинам. Любое заметное число — повод чинить немедленно | Сохранить имя, добавить `reason` |
| `contact_vk_click` | Переход во ВКонтакте. Защита как у телефона | `place`, `page` | Нужна ли ссылка на видном месте. Переводится в главные, если владелец подтвердит, что принимает заказы в сообщениях ВК | Новое |
| `route_open` | Нажата ссылка маршрута, карты (Яндекс, 2ГИС) или развёрнута карта. Не чаще раза за 30 секунд | `target` (`yandex`, `2gis`, `map`), `place`, `page` | Сколько людей собираются приехать; достаточно ли заметен адрес | Новое |
| `kp_download` | Нажата ссылка на КП в PDF. Один раз на загрузку страницы | `page`, `place` | Интересуются ли компании; с каких страниц; стоит ли держать КП актуальным | Новое |

### 4.3. Что убираем из старого набора

| Старое событие | Что с ним |
|---|---|
| `calc_order` | Убрать: заменено на `calc_add` (позиция в смете) + `calc_complete` (переход к оформлению) |
| `order_open` | Переименовать в `form_open` |
| `form_submit_attempt` | Убрать: число попыток равно сумме успехов и ошибок |
| `calc_add`, `file_attached`, `form_validation_error`, `form_submit_success`, `form_submit_error` | Сохранить имена, дополнить параметрами |

### 4.4. Что сознательно не отслеживаем

| Что | Почему |
|---|---|
| Каждое нажатие в калькуляторе | Засоряет отчёты; хватает «первое изменение каждого вида» |
| Открытие чата, открытие сметы, прокрутка до блоков, раскрытие вопросов | Не ведут к конкретному решению; при необходимости видны в вебвизоре и на карте кликов |
| Нажатие на e-mail | Письма владелец и так видит в почте |
| Переходы на площадки отзывов | Решения из этого не следует |
| «Брошенная форма» | Надёжно поймать нельзя; считается как разница `form_open` и отправок |

## 5. Как отличать частных клиентов от компаний

| Признак | Надёжность | Как используется |
|---|---|---|
| Переключатель в форме «частное лицо / организация» | Высокая — человек сказал сам | `client_type` в событиях формы и поле в заявке |
| Заявка отправлена в режиме «организация» (страница компаний) | Высокая | То же |
| Заполнено название организации | Высокая | Только в базе заявок; в Метрику сам текст не передаём |
| Скачал КП, смотрел страницу компаний или спецодежды | Средняя — это интерес, не факт | Сегмент в Метрике «интерес компаний» |
| Тираж выше предела (`calc_over_limit`) | Низкая — это может быть и класс | Не считаем компанией, смотрим отдельно |

Правило: до отправки формы тип клиента — `unknown`. Мы не угадываем его по поведению и не записываем догадку в заявку. Группы (класс, команда) могут быть и частными, и организациями — их определяет только переключатель.

## 6. Как связать заявку с источником трафика

Цель: владелец открывает заявку и видит, откуда пришёл человек и на какую сумму заказ.

**Что сохранять вместе с заявкой** (новые поля таблицы `orders`):

| Поле | Что это | Откуда |
|---|---|---|
| Номер заявки | Короткий номер, который видит и клиент | Сервер |
| Источник первого визита | Метки `utm_source`, `utm_medium`, `utm_campaign` (если были) | Сайт запоминает при первом заходе |
| Источник последнего визита | Те же метки для визита, в котором оставлена заявка | Сайт |
| Сайт-источник | Только домен, с которого пришли (`yandex.ru`, `avito.ru`, `2gis.ru`, `vk.com`) или «прямой заход» | Сайт, при первом заходе |
| Первая страница | Путь страницы входа | Сайт |
| Страница заявки | Уже сохраняется | — |
| Дата первого визита | Сколько времени прошло от знакомства до заявки | Сайт |
| Тип клиента, режим формы, макет (есть / фото / нет), желаемая дата | Из формы | Сайт |
| Устройство | Телефон или компьютер | Сайт |
| Идентификатор посетителя Метрики | Чтобы при желании найти визит в Метрике и позже загружать туда итог заказа | Метрика отдаёт его сайту (проверить способ в справке) |
| Состоялся ли заказ, итоговая сумма | Раздел 8 | Владелец |

**Упрощённый «источник» одной строкой** для уведомления в Telegram и для сводки: поиск Яндекса · поиск Google · Яндекс Карты · 2ГИС · Авито · ВКонтакте · Telegram · метка (название) · прямой заход · другое. Правила отнесения пишутся один раз в коде сервера.

**Чтобы это работало, ссылки на сайт в своих карточках нужно пометить.** В карточках Яндекс Карт, 2ГИС, Авито, в шапке групп ВК и Telegram, в QR-кодах на печатной продукции ссылку на сайт стоит давать с меткой (например, `?utm_source=avito`). Иначе переход из приложения часто выглядит как «прямой заход». Это ручная работа владельца (мы подготовим готовые ссылки).

**Ограничения, о которых честно:**
- Человек нашёл сайт в поиске с телефона, а заявку оставил вечером с компьютера — связи не будет.
- Запомнить источник можно только в хранилище браузера. Это относится к теме согласия (раздел 10).
- Идентификатор Метрики рядом с телефоном в базе — это связь обезличенного идентификатора с человеком. Пометка для юридической части; если владелец решит не хранить — источник всё равно останется, пропадёт только возможность сверки с Метрикой.

## 7. Учёт звонков без коллтрекинга

| Что можно измерить | Как | Насколько точно |
|---|---|---|
| Нажатия на номер на сайте | `contact_phone_click` | Хорошо на телефонах; это намерение, а не состоявшийся разговор |
| С каких страниц и из каких источников нажимают | Отчёты Метрики по этой цели | Хорошо |
| Звонки из карточек Яндекс Карт и 2ГИС | Статистика в кабинетах этих площадок (проверить) | Только там, мимо сайта |
| Общее число входящих звонков | Детализация у оператора связи | Число есть, источника нет |

| Чего измерить нельзя | Почему |
|---|---|
| Звонок человека, который прочитал номер на компьютере и набрал с телефона | Нажатия нет |
| Какой звонок привёл к заказу и на какую сумму | Нет связи звонка с визитом |
| Точный источник звонка | Для этого и существует коллтрекинг |

Самый дешёвый способ закрыть пробел — вопрос «как вы нас нашли?» при разговоре и короткая отметка. Делать это или нет, решает владелец; на аналитику сайта это не влияет.

Вывод для отчётов: нажатия на телефон показываем отдельной строкой «обращения по телефону (нажатия)» и не складываем с заявками в одну цифру без пояснения.

## 8. Учёт результата: заявка → состоявшийся заказ

Сейчас сайт знает только о заявке. Стал ли она заказом и на какую сумму — нигде не записано.

| Вариант | Что делает владелец | Что нужно сделать нам | Оценка |
|---|---|---|---|
| 0. Пока не делаем | Ничего | Ничего | Честный вариант на старте: сначала наладить учёт заявок и источников |
| 1. Кнопки под заявкой в Telegram | Под сообщением о заявке нажимает «Заказ состоялся» или «Не состоялся»; при желании вводит итоговую сумму | Доработать уведомление и приём нажатий (похожий механизм уже написан на старом сайте для отзывов, ФК 4.8) | **Рекомендуем как первый шаг после запуска.** Занимает секунды, не требует новых программ |
| 2. Загрузка итогов в Метрику | Ничего дополнительно | Раз в неделю автоматически передавать в Метрику состоявшиеся заказы по идентификатору посетителя (возможность «офлайн-конверсии», проверить условия) | Только после того, как вариант 1 прижился. Нужен при платной рекламе |

Чего этот учёт не даст: заказы от тех, кто позвонил или пришёл в мастерскую без заявки, в нём не появятся.

## 9. Воронки в Метрике (составные цели)

Составная цель — это цепочка шагов; Метрика показывает, сколько людей дошло до каждого. Шаги должны идти в одном визите.

| Воронка | Шаги | На какой вопрос отвечает |
|---|---|---|
| А. Расчёт → заявка | `product_view` → `calc_start` → `calc_complete` → `form_submit_success` | На каком шаге теряем людей, которые начали считать |
| Б. Быстрая заявка | `product_view` → `form_open` → `form_submit_success` | Мешает ли сама форма. Сравнение с воронкой А показывает, какой путь короче и результативнее |
| В. Компании | посещение страницы компаний (условие по адресу) → `form_open` → `form_submit_success_b2b` | Доходят ли компании до заявки |
| Г. Интерес компаний (простая цель) | `kp_download` | Сколько компаний взяли КП и не написали |

Замечания:
- В воронке Б часть людей придёт из шапки на страницах без `product_view` (главная, статьи). Для них смотреть простую пару `form_open` → `form_submit_success`.
- `calc_add` в воронку А не включён намеренно: человек может нажать «Заказать», минуя «В смету». Смотрится отдельно.
- Простые цели (по одному событию) заводятся на каждое событие из раздела 4 — иначе их не будет в отчётах.
- У бесплатного счётчика есть предел числа целей (проверить в кабинете). 20 событий и 3 составные цели в него укладываются с запасом по нашим сведениям.

## 10. Согласие, cookies и персональные данные

**Факт о старом сайте:** Метрика с вебвизором загружается независимо от плашки cookies; в плашке есть только «Понятно», отказа нет (ФК 11.2 №6). Юридическую часть владелец отложил.

**Это вопрос к владельцу, мы его не решаем.** Варианты, из которых выбирать:

| Вариант | Что это значит для аналитики |
|---|---|
| Оставить как есть (уведомление, Метрика работает сразу) | Данные полные. Риск по закону о персональных данных оценивает владелец |
| Метрика включается только после согласия | Данных станет заметно меньше, и они будут смещены (соглашаются не все). Воронки останутся пригодными для сравнения «до и после», но абсолютные числа — нет |
| До согласия — Метрика без вебвизора, после — с вебвизором | Промежуточный вариант; допустим ли он, решает юридическая часть |

Независимо от выбора, заявки в базе считаются полностью — на них плашка не влияет. Поэтому главный показатель не пострадает при любом варианте.

**Вебвизор не должен записывать персональные данные.** Что закладываем в требования:
1. Все поля форм (имя, телефон, почта, организация, ИНН, комментарий, «другой цвет», «что за вещь», описание идеи), окно чата и список позиций сметы помечаются служебными классами Метрики, которые запрещают запись нажатий клавиш и скрывают содержимое блока в записи (в справке Метрики это классы вида `ym-disable-keys` и `ym-hide-content` — точные названия проверить перед внедрением).
2. На настройки по умолчанию не полагаемся: защита ставится явно.
3. На панели владельца `/admin` Метрики нет вообще.
4. Телефон, имя и почта не попадают в адрес страницы и в параметры событий.
5. Имена файлов не передаются (в них бывают фамилии).
6. Проверка после внедрения: отправить тестовую заявку, найти свой визит в вебвизоре и убедиться, что в записи вместо введённого — пусто или звёздочки.

**Что ещё отметить для юридической части:** хранение источника в браузере; идентификатор Метрики рядом с телефоном в базе; срок хранения заявок; текст согласия под формой.

## 11. Что смотреть регулярно

### Раз в неделю (10 минут)

| Показатель | Где | Какой вывод |
|---|---|---|
| 1. Число заявок и их сумма | База заявок (сводка) | Главная цифра. Падение при той же посещаемости — искать поломку или неудачное изменение |
| 2. Ошибки отправки (`form_submit_error`) и расхождение «заявок в Метрике / заявок в базе» | Метрика и база | Должно быть около нуля. Любой рост — чинить в первую очередь |
| 3. Обращения мимо формы: нажатия на телефон, Telegram, MAX | Метрика, цели | Если их больше, чем заявок, — люди предпочитают живой контакт; усиливать его, а не форму |

### Раз в месяц (30–40 минут)

| Показатель | Где | Какой вывод |
|---|---|---|
| 4. Заявки и сумма по источникам | База заявок | Какие площадки приносят заказы — чему уделять время (карточка на картах, Авито, соцсети) |
| 5. Воронка «расчёт → заявка» по шагам | Метрика, составная цель А | Где самая большая потеря: первый экран, калькулятор или форма — это и улучшать следующим |
| 6. Страницы изделий: просмотры → начало расчёта → заявки | Метрика | Страницы с интересом, но без заявок — первые кандидаты на переделку |
| 7. Доля компаний: заявки и сумма, скачивания КП | База и Метрика | Стоит ли развивать раздел для компаний |

Дополнительно раз в месяц в Вебмастере: по каким запросам показывают сайт и нет ли ошибок. После запуска варианта 1 из раздела 8 добавляется восьмой показатель — доля заявок, ставших заказами.

Чтобы владельцу не ходить по кабинетам, показатели 1, 4 и 7 можно присылать готовой сводкой в Telegram раз в неделю (данные уже в базе). Это предложение на будущее, не обязательная часть.

## 13. Что настраивается вручную и чего нельзя проверить без доступа

**В кабинете Метрики вручную:**
- 20 простых целей по событиям и 3 составные цели (раздел 9);
- включение вебвизора и согласие с его условиями;
- фильтр своих посещений;
- доступ для нас (хотя бы на просмотр) — выдаёт владелец;
- при желании — связь с Вебмастером.

**В кабинете Вебмастера вручную:** подтверждение прав на сайт сохранить, загрузить новую карту сайта, при смене адресов — проверить переадресации.

**В карточках площадок вручную (владелец):** ссылки на сайт с метками.

**Чего мы не можем проверить без доступа:**
- настроены ли сейчас цели и есть ли по ним история;
- сколько посетителей и откуда — значит, все прикидки про трафик остаются гипотезами;
- включён ли и работает ли вебвизор, что он записывает сейчас;
- точные названия и поведение служебных возможностей Метрики (передача суммы как дохода, классы защиты полей, предел числа целей, загрузка итогов заказов) — помечены «проверить»;
- что показывает статистика карточек на Яндекс Картах и в 2ГИС.

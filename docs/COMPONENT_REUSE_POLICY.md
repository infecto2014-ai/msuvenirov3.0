# Правила повторного использования и адаптации компонентов

Утверждено владельцем 12.11.2026 («Нулевой этап 2»). Действует на всех этапах: концепции, прототипы, production. Связанные документы: `DESIGN_RESOURCE_REGISTRY.md` (каталог), `DESIGN_REFERENCE_BOARD.md` (референсы), `RESOURCE_LICENSES.md` (лицензии).

## 1. Главное правило

Перед разработкой любого сложного или повторно используемого компонента (меню, галерея, слайдер, фильтр, анимация, форма, таблица, калькулятор) — **сначала открыть `DESIGN_RESOURCE_REGISTRY.md`** и проверить, есть ли качественная бесплатная реализация. Если в реестре нет — поискать в интернете и дополнить реестр. Только потом решать: взять готовое, адаптировать или писать своё.

Дизайн не подчиняется библиотеке: если готовый компонент не подходит концепции, фирменному стилю или решениям владельца (CLAUDE.md) — не используем.

## 2. Две категории источников

**Категория A — референсы (только изучать).** Сайты-галереи и чужие проекты: композиция, типографика, иерархия, подача товара, навигация, анимации, сценарии. Запрещено: копировать сайт целиком, воспроизводить чужой фирменный стиль, брать чужие тексты, фото, логотипы, иллюстрации, код закрытых сайтов.

**Категория B — материалы для использования.** Открытые компоненты, шрифты, иконки, изображения, библиотеки, лицензия которых проверена и разрешает коммерческое использование. Их можно адаптировать под нашу дизайн-систему с соблюдением лицензии.

## 3. Проверка перед использованием (все пункты обязательны)

1. **Лицензия проверена по первоисточнику** (файл LICENSE в репозитории или страница лицензии на сайте автора), а не по пересказу. Проверяем: коммерческое использование, атрибуция, право изменять, ограничения на распространение, не Pro/платная ли версия, нет ли Non-Commercial и особых условий автора.
2. Лицензия неизвестна или неоднозначна → **не используем** до дополнительной проверки.
3. Платные компоненты, шаблоны, закрытые материалы → **только с разрешения владельца**.
4. Запись в `RESOURCE_LICENSES.md`, раздел «Использовано в проекте»: название, ссылка, конкретный компонент/файл, лицензия, коммерческое использование, атрибуция, дата проверки, внесённые изменения. Без записи ресурс в проект не попадает.
5. Если лицензия требует сохранить уведомление (MIT, ISC, Apache, OFL) — оно сохраняется: в заголовке файла или в `THIRD_PARTY_NOTICES`.

## 4. Технические правила

- **Не подключать десятки библиотек.** Берём конкретный компонент под конкретную задачу.
- **Не смешивать UI-библиотеки без причины**: одна основа для компонентов, одна библиотека анимаций. Вторая — только с обоснованием в реестре.
- **Совместимость со стеком** проверяется до использования. Компонент под React + Tailwind в проект на другом стеке не тащим «как есть»: либо переносим приём (разметка + CSS) в свой компонент, либо отказываемся.
- **Копирование кода предпочтительнее зависимости**, когда компонент маленький и лицензия позволяет (подход shadcn: код живёт в проекте, адаптирован под наши токены). Зависимость ставим, когда это настоящая библиотека с логикой (карусель, лайтбокс, анимационный движок).
- **Нет тяжёлым скриптам ради одного эффекта.** Ориентир: эффект не должен добавлять больше ~15 КБ gzip к странице, если он не ключевой для концепции; сначала ищем CSS-решение. 3D/WebGL — только отложенной загрузкой и с запасным статичным вариантом.
- **Только локальные файлы**: шрифты, иконки, скрипты, изображения лежат в проекте (npm или `public/`), без чужих CDN — сайт работает из России, внешние CDN могут быть недоступны и тормозят.
- **Иконки** — отдельными SVG, не шрифтом и не целым набором.
- **Шрифты** — только с кириллицей, только нужные начертания, variable-версия, если есть.
- **Доступность и производительность**: готовый компонент должен работать с клавиатуры, уважать `prefers-reduced-motion`, не ломать мобильную версию. Иначе дорабатываем или не берём.
- **Массово ничего не устанавливаем.** Новая зависимость — одна за раз, с записью в реестр и проверкой сборки (`npm run build`, `npm test`).

## 5. Адаптация под фирменный стиль

- Взятый компонент переводится на наши токены (цвета, радиусы, шрифты, отступы) — «чужой» вид на сайте не остаётся.
- Изменения фиксируются в `RESOURCE_LICENSES.md` (столбец «Изменения»).
- Логотип — только настоящий логотип владельца; иконочные наборы с чужими товарными знаками (логотипы брендов) используются только для обозначения самих этих сервисов (Telegram, Авито и т.п.).

## 6. Фотографии и изображения

Три вида изображений не смешиваются и не выдаются одно за другое:

1. **Реальные фото** мастерской и заказов — портфолио, отзывы, «о нас».
2. **Предметные рекламные изображения / визуализации**, соответствующие реальному изделию.
3. **Сгенерированные демонстрационные визуализации** — с честным обозначением, где это нужно.

- Стоковые фото — только для атмосферы и окружения. **Нельзя** выдавать сток за наши работы, производство, продукцию или клиентов; в портфолио и отзывах стока нет.
- Приоритет для товарных изображений: реальное фото → предметная визуализация → сгенерированная демонстрация.
- **Принт на товаре ≠ картинка на сайте.** Лицензия на показ фото на сайте не даёт права печатать его на изделиях. Любое стоковое изображение в роли принта (на мокапе или на реальном товаре) проверяется отдельно; по умолчанию для демонстрационных принтов используем собственную графику, логотип владельца или макеты с разрешения клиентов.
- Узнаваемые люди, бренды, товарные знаки на стоковых фото — не используем в рекламном контексте.

## 7. Кто что делает (по `MODEL_POLICY.md`)

- Поиск ресурсов, проверка лицензий, ведение реестров — Sonnet (`project-auditor` / `content-editor`); проверка ссылок и наличия записей — скриптом, когда появится список используемых ресурсов.
- Выбор библиотеки-основы, решение «взять готовое или писать своё» для сложных компонентов — Opus (`frontend-engineer`, `creative-director`).
- Решения, затрагивающие стек и концепцию в целом, — Fable (главная сессия).

## 8. Когда обращаться к базе повторно

Обязательно перед: разработкой трёх концепций, интерактивными прототипами, production-вёрсткой, каждым новым сложным компонентом. Реестр дополняется по ходу — это не разовое исследование.

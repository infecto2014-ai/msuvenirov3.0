# Карта распределения задач (Agent Routing)

Правила — `docs/MODEL_POLICY.md`. Определения агентов — `.claude/agents/*.md`. Проверка — `node scripts/check-agents.mjs`.

## Агенты

| Агент | Модель | Инструменты | Задачи |
|---|---|---|---|
| `project-director` | Fable 5.2 | только чтение | Стратегия, выбор концепции, противоречия между направлениями, утверждение этапов, эскалации от Opus |
| `creative-director` | Opus 5.5 | чтение, правка, Bash | Креативные концепции, дизайн-система, глубокая критика дизайна |
| `ux-architect` | Opus 5.5 | чтение, правка, Bash | UX-архитектура, структура и навигация, архитектура каталога |
| `frontend-engineer` | Opus 5.5 | чтение, правка, Bash | Сложные компоненты, калькулятор и математика цен, сложные анимации, сложные технические проблемы |
| `seo-strategist` | Opus 5.5 | чтение, правка, Bash, поиск | SEO-стратегия, семантика, шаблоны метаданных |
| `content-auditor` | Sonnet 5.5 | только чтение + Bash | Аудит и инвентаризация контента, проверка ссылок |
| `content-migrator` | Sonnet 5.5 | чтение, правка, Bash | Перенос текстов и данных, однотипные правки, форматирование |
| `component-builder` | Sonnet 5.5 | чтение, правка, Bash | Стандартные компоненты и типовые страницы по утверждённому макету, простые исправления |
| `seo-filler` | Sonnet 5.5 | чтение, правка, Bash | Метаданные по готовой SEO-стратегии |
| `test-writer` | Sonnet 5.5 | чтение, правка, Bash | Обычные тесты, проверка сборки и ссылок скриптами |

Ни у одного агента нет инструмента `Agent`: создавать и вызывать агентов может только главная сессия.

## Передача задачи

1. Главная сессия определяет сложность задачи по `MODEL_POLICY.md` §2 и выбирает агента из таблицы.
2. Если задача детерминированная (сборка, тесты, ссылки, форматы) — запускает скрипт, агента не зовёт.
3. Если задача на 1–2 мелкие правки — делает сама (вызов агента дороже).
4. Агенту передаётся: цель, список файлов, которые можно менять, 1–3 документа для чтения, критерий готовности.
5. Независимые задачи с непересекающимися файлами — параллельно; иначе последовательно.
6. Результат агента главная сессия проверяет сама (сборка, тесты, при вёрстке — скриншот) и пишет строку в `MODEL_USAGE_LOG.md`.

## Эскалация

| Откуда | Куда | Когда |
|---|---|---|
| Sonnet-агент | Opus-агент того же направления | 2 неудачные попытки, сложная неоднозначность, нужно архитектурное решение |
| Opus-агент | `project-director` (Fable) | Нужно менять общую стратегию или несколько согласованных решений |
| `project-director` | владелец | Решение меняет то, что владелец уже согласовал (CLAUDE.md) |

Соответствие направлений Sonnet → Opus: `content-auditor`/`content-migrator` → `ux-architect`; `component-builder` → `frontend-engineer` (вёрстка/логика) или `creative-director` (вид); `seo-filler` → `seo-strategist`; `test-writer` → `frontend-engineer`.

Агент не эскалирует сам: возвращает отчёт с пометкой `ЭСКАЛАЦИЯ → <модель>: <причина>`, дальше решает главная сессия.

## 2. Хаб ↔ дочерние

- **Хаб → дочерние:** карточки изделий с ценой «от» (из прайса), таблица «какое изделие выбрать», калькулятор категории. Каждая дочерняя страница — минимум одна ссылка из содержимого хаба.
- **Дочерняя → хаб:** крошка + одна ссылка в тексте («Все виды одежды для печати», «Другая полиграфия»).
- **Дочерняя → соседние:** блок «Ещё печатаем» (правила — раздел 4) + сравнения внутри страницы (худи ↔ футболки, хлопковый шоппер ↔ сублимация).
- Хабы: `/pechat-na-odezhde` (7 страниц одежды), `/poligrafiya` (визитки, календари, широкоформат), `/korporativnym-klientam` (`/korporativnye-podarki` + B2B-изделия), `/stati` (статьи), `/portfolio` (кейсы), `/uslugi` (всё).

## 4. Блоки «С этим заказывают» и «Ещё печатаем»

### «С этим заказывают» (комплект к текущему заказу)

1. 3–4 изделия, которые реально покупают **вместе** с текущим (тот же клиент, тот же повод), а не просто соседи по меню.
2. Только изделия с ценой в прайсе (карточка показывает «от N ₽» из прайса).
3. Не ссылаться на саму страницу и на её хаб.
4. Для одежды — сразу после калькулятора (решение владельца по порядку блоков).

## 5. Ссылки из статей

1. Первая ссылка — в первых 2–3 абзацах, на главную для темы коммерческую страницу (Новый год → `/podarki` или кружки/фотоподарки; DTF или сублимация → `/pechat-na-odezhde`).
2. Каждая идея с ценой — ссылка на страницу изделия («Подробнее») и действие «Заказать».
3. Не больше 1 ссылки на одну и ту же страницу из текста статьи (кнопки идей не считаются, если ведут к разным изделиям).
4. Подарочные статьи — блок «Для компаний» со ссылкой на `/korporativnye-podarki` и КП.
5. «Смотрите также»: 2–4 статьи той же или соседней рубрики + 1 страница задачи.
6. Статья не ссылается анкором с точной коммерческой фразой «печать на футболках в Калининграде» — анкор описательный («футболку с фото можно заказать от одной штуки»).
7. Новая статья появляется в `/stati`, в «Смотрите также» минимум двух старых статей и в блоке «Идеи/Советы» хотя бы одной страницы изделия — иначе у неё будет мало входящих (в 2.0 у новогодней статьи было всего 2 входящих страницы).

## 6. Ссылки в калькулятор (`?calc=`)

- Формат как в 2.0: `?calc=<категория>:<изделие>` открывает калькулятор с нужным изделием. Будущая «ссылка на расчёт» с опциями и количеством — всё внутри одного параметра `calc` (или во фрагменте `#…`), чтобы не добавлять новых параметров.
- **Куда ведут:** на страницу изделия, а не на `/price` — чтобы ссылочный вес и посетитель шли на посадочную страницу. Пример: идея «Кружка-хамелеон» в статье → `/pechat-na-kruzhkah?calc=mugs:mug`. На `/price?calc=…` — только из мест, где речь именно о сравнении/смете (B2B «Собрать смету» → `/price`).
- На той же странице — якорь `#calc`, без перезагрузки.
- Canonical у адресов с `?calc=` — без параметра; в Яндексе — Clean-param `calc` (как в 2.0).
- Текстовые ссылки в содержимом (анкоры в абзацах) — на чистые адреса. `?calc=` — только у кнопок «Рассчитать», «Заказать похожее», «Другой тираж».
- Скрипт проверки: изделие и категория в `?calc=` существуют в прайсе (иначе калькулятор откроется пустым).

## 8. Правила анкоров

1. **Разнообразие.** Для одной страницы-цели используем 3–5 разных анкоров по сайту: название из меню («Футболки»), описательный («футболка с вашим фото»), действие («посчитать футболки»), с уточнением («детские футболки 98–164»). Точная коммерческая фраза «печать на футболках в Калининграде» — не чаще одного раза на весь сайт (например, в SEO-тексте главной), не в каждой карточке.
2. **«Калининград» в анкорах не ставим** (кроме редкого случая в тексте главной).
3. **Анкор отражает, что за ссылкой.** «Подробнее» — только рядом с ясным заголовком карточки; кнопка «Подробнее» дополняется скрытым для глаз, но читаемым текстом, если по-другому нельзя (для экранных дикторов и поиска).
4. **Одна страница-цель — одна ссылка из текста страницы-источника.** Повторные ссылки на ту же страницу (меню, крошки, карточки) допустимы, но в тексте — одна.
5. **Анкоры защищают от каннибализации:** анкор с главной формулировкой страницы X ведёт только на X (например, «DTF-печать листами» → только `/dtf-pechat`; «сублимационная печать» → только `/sublimacionnaya-pechat`; «корпоративные подарки» → только `/korporativnye-podarki`; «мерч с логотипом» → только `/korporativnym-klientam`).
6. Картинки-ссылки — с осмысленным `alt` (что на фото), без перечисления ключевых слов.
7. Никаких скрытых ссылок, ссылок одним цветом с фоном, «облаков тегов».

## 9. Глубина и страницы-сироты

- **Глубина:** все страницы приоритета 1 и 2 — **не дальше 2 нажатий от главной** (почти все — 1 нажатие через меню). Статьи и кейсы — не дальше 3 нажатий (главная → `/stati` или `/portfolio` → страница). Без учёта меню (только по ссылкам в содержимом) — не дальше 3 нажатий.
- **Сироты исключаются так:**
  1. Единый реестр страниц (тот же, из которого строятся меню, sitemap, крошки, `llms.txt`): страница без записи в реестре не собирается.
  2. Для каждой индексируемой страницы — минимум **3 входящие ссылки из содержимого** других страниц (не считая шапки, подвала и крошек); для статей — минимум 2.
  3. Новая страница добавляется вместе с ссылками на неё (таблица ниже — обязательный минимум).
  4. Проверка скриптом после каждой сборки (раздел 11).
- Служебные страницы (`/404`, `/admin`, `/card`, `/kp`) — без входящих ссылок из меню; на `/kp` и PDF ведут только кнопки «Скачать КП».

## 10. Ссылки, которых не должно быть

- На адреса с переадресацией (`/pechat_na_tkani`, `/mug-print`, `*.html`, со слэшем) — ссылаться только на конечные адреса.
- На `/404`, `/admin`, `/card`, `/kp` из содержимого (кроме кнопки «Скачать КП» → PDF).
- На страницы с noindex из меню (кроме согласия на обработку данных у форм, если будет).
- Внешние ссылки на площадки отзывов (Яндекс Карты, 2ГИС, Авито) — только в блоке отзывов, на `/otzyvy`, в контактах и подвале; открываются в новой вкладке; без `nofollow` не обязательно (это наши карточки).

## 11. Как проверять скриптом после сборки

Предлагаемый скрипт (в репозитории 3.0, например `scripts/seo/check-links.mjs`; пишется на этапе разработки) обходит собранные HTML-файлы и проверяет:

1. **Битые ссылки:** каждая внутренняя ссылка ведёт на существующую страницу с кодом 200 (или на файл).
2. **Ссылки на переадресации:** ни одной внутренней ссылки на адрес из таблицы переадресаций `SITE_MAP.md`, раздел 6.
3. **Глубина:** обход в ширину от `/` — у каждой индексируемой страницы глубина ≤ 2 (статьи и кейсы ≤ 3); отдельно — глубина без учёта шапки и подвала (≤ 3).
4. **Сироты:** у каждой индексируемой страницы ≥ 3 входящих ссылки из содержимого (для статей ≥ 2); содержимое — всё внутри `<main>`, без шапки, подвала и крошек.
5. **Обязательные ссылки:** для каждой строки таблицы раздела 9 — есть ли ссылка из содержимого источника на цель (таблица хранится в данных как список пар).
6. **Анкоры:** одна и та же точная фраза-анкор не ведёт на две разные страницы; главная фраза страницы не используется анкором для другой страницы (список фраз — из `SEO_KEYWORD_MAP.md`).
7. **`?calc=`:** категория и изделие существуют в прайсе; canonical таких адресов — без параметра.
8. **Реестр ↔ sitemap ↔ меню:** каждая индексируемая страница есть в sitemap и достижима из меню или хаба; в sitemap нет noindex, переадресаций и адресов с параметрами.
9. **Крошки:** видимые крошки совпадают с BreadcrumbList и с родителем из реестра.
10. **FAQ-дубли:** одинаковая формулировка вопроса не стоит на двух страницах.

Результат — отчёт в консоли и ненулевой код выхода при ошибках 1, 2, 4, 7, 8 (сборка не проходит); остальное — предупреждения.

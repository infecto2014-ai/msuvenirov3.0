Прежнее содержимое лежит в ветке `backup/before-clean-15-11` — это только архив: правила оттуда больше не действуют, пока владелец не вернёт их сам.

## Superpowers — работает ВСЕГДА (владелец, 15.11.2026)

- Включается сам: хук `SessionStart` в `.claude/settings.json` запускает `.claude/hooks/superpowers-session-start`, и в начале каждого сеанса (а также после очистки и сжатия разговора) Claude получает правила `using-superpowers`. Отдельной просьбы владельца для скилов superpowers не нужно.
- Порядок работы: `brainstorming` (сначала вопросы и согласованное описание задачи) → `writing-plans` (план по шагам) → `subagent-driven-development` или `executing-plans` (выполнение, помощники + проверка) → `test-driven-development`, `requesting-code-review`, `verification-before-completion` → `finishing-a-development-branch`. Ошибки — `systematic-debugging`.
- Особенности установки:
  - Скилы лежат в проекте, а не как плагин, поэтому называются без приставки: `brainstorming`, а не `superpowers:brainstorming`. Где в текстах скилов написано `superpowers:<имя>` — вызывать `<имя>`.
  - Описания задач сохраняются в `docs/superpowers/specs/`, планы — в `docs/superpowers/plans/`; служебная папка `.superpowers/` — в `.gitignore`.
  - Отправка статистики авторам отключена (`SUPERPOWERS_DISABLE_TELEMETRY` в `.claude/settings.json`).
  - Скилл `using-git-worktrees` в облачном сеансе не нужен: работать в ветке, которую задаёт сеанс.
  - Слова владельца и эта памятка важнее правил скилов. С владельцем — простым языком, вопросы по одному и по делу.
  - Обновление: скачать свежий `obra/superpowers`, заменить папки скилов и файл хука, поправить версию здесь.
  - Если скилы ведут себя странно — скилл `diagnosing-superpowers`.

## Стек и команды
- Astro 5.16.x (строго `~5.16.16`: на сервере Node ≥ 18.20.8, не обновлять до 6+ без проверки сервера), статика, `build.format: 'file'` (`/price` → `price.html`), `trailingSlash: 'never'`. Preact — только для окна заявки (`src/components/islands/OrderDialog.tsx`). Шрифт Onest — локально (`@fontsource-variable/onest`), значки Lucide вставлены как SVG (`src/components/ui/Icon.astro`).
- `npm run dev` — локально (порт 4321); `npm run build` — проверка типов + сборка в `dist/`; `npm test` — тесты (цены, адрес, данные главной, смета, картинки); `npm run check:links` — после сборки: все ссылки и файлы на месте, старого адреса нет.
- `node scripts/shots.mjs <папка>` (после `npm run build`) — снимки главной на 1440, 1024, 768 и 360 px, ошибки консоли и горизонтальная прокрутка; `--no-js` — то же без JavaScript. Playwright берётся из окружения.
- Тестовая копия — GitHub Pages репозитория (`.github/workflows/preview.yml`, ссылки получают префикс через `scripts/preview-rewrite.mjs`, закрыта от индексации). Форма там не отправляет — функции Supabase не развёрнуты; окно показывает ошибку и предлагает позвонить или написать в Telegram.

## Одежда — шаблон и худи (16.11.2026)
- Описание — `docs/superpowers/specs/2026-11-16-clothing-pages-design.md`. Все страницы одежды — один шаблон `src/layouts/GarmentPage.astro` (блоки `src/components/garment/*`); каждая страница — один файл данных `src/data/garments/<страница>.ts` типа `GarmentPage` (+ тест). Футболки — `tshirt.ts`, худи — `hoodie.ts`. Остальные страницы одежды делаются так же (владелец: «по аналогии все страницы категории одежда запускаем в работу»). Новая страница: файл данных, `src/pages/<адрес>.astro` из двух строк, адрес в `REAL_PAGES` (`src/lib/stubs.ts`), картинки котов в `docs/IMAGES.md`.
- Порядок блоков: первый экран → калькулятор → готовые варианты → конструктор → «Подробнее об изделии» → работы → отзывы → вопросы → открытая таблица цен. Рейтинги площадок над отзывами — только на главной.
- В калькуляторе каждой страницы одежды есть плитки изделий, в том числе «свой / своя / своё» (печать на вещи клиента, считается только печать, цвет скрыт): у футболок — «Футболка унисекс», «Детская», «Своя футболка»; у худи — «Худи» и «Своё худи». Плитки — `calc.tiles` в файле данных; у плитки «свой» стоит `own: true` (на ней «печать от», в смете — название плитки; для своей вещи без выбора «наша / своя», например спецодежды, — `product: 'own-item'` и `own: true`). Список изделий страницы (калькулятор, цена «от» на первом экране и в разметке) берётся из плиток.
- Модель данных шаблона (16.11.2026): разделы «Подробнее» — `colors`, `specs`, `prints`, `sizes`, `care` — необязательны, без данных раздел не выводится. Цвета — `colors: { product, sub }`: список и пометки «в наличии» / «от N шт» считаются из правил `pricing.ts` (`colorChoices`), не из подсказок. Характеристики — `specs: { items, sub, title?, icon?, todo? }` (по умолчанию «Ткань и характеристики» и значок `shirt`). Размеры принтов — `prints: { sizes, sub, shape, caption }`, контуры изделий и подписи A/B/C — `src/data/garments/shapes.ts` (новое изделие — новый контур там). Отзывы: если про изделие меньше трёх и они добраны с главной — заголовок «Отзывы клиентов».
- Футболки: принтов до 5 на взрослой, детской и своей; на детской — размеры принта до А3; взрослая размерная сетка верная (без пометки «ориентировочные»). Итог калькулятора — спокойная белая карточка, синие только сумма и кнопка.
- Худи: 2 600 ₽ при любом количестве (`HOODIE_BLANK` в `pricing.ts`) + печать; цвета только белый и чёрный, без минимума; принтов до 4; больше 50 шт — индивидуально; характеристики и размеры подтверждены владельцем. Фото вариантов: первый — настоящая работа `portfolio-5`, остальные — слот `hoodie-product` (спокойное фото изделия владелец пришлёт; неоновое фото 2.0 не подошло), до этого подписанная заглушка. Схема размеров принтов на худи нарисована в коде (`src/data/garments/shapes.ts`, контур с капюшоном и карманом «кенгуру»).
- Шапка: значка «Смета» нет, число позиций сметы — кружок на кнопке «Заявка»; смета по-прежнему открывается в окне заявки.
- Коты для первых экранов (`hoodie-hero`, `tee-hero` и др.) владелец пришлёт позже; пока — подписанные заглушки (список — `docs/IMAGES.md`).
